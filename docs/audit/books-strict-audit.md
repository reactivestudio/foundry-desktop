## По книгам

### Clean Architecture — Martin

#### 07-single-responsibility-principle — Code is broadly SRP-clean — presenters, decoder, runner and ports are split by actor with no god class, layer-mixing class, or Active Record. Two minor divergent-/shotgun-placement deviations where a user-facing command string and a start-eligibility rule live outside their declared owning module.

- **[minor]** `Packages/FoundryKit/Sources/FoundryFeatures/FeedViews.swift:77 (ResultCardView)` — *7.5-7 Shotgun Surgery / divergent placement: one responsibility (the user-facing resume-command spelling) minted outside its owning module*: The view builds "claude --resume \(result.sessionID)" inline, while RunStrings in RunPresentation.swift declares itself «единственное место, где рождается UI-текст». The resume-command format now has an axis of change living in a leaf view; the same `claude --resume` concept is also spelled in RunConsoleView.swift:113 prose — change the invocation and you hunt multiple sites. → **Mint the command via a `RunStrings.resumeCommand(id:)` helper and call it from the view. Pure string move, no visual change (identical output).**
- **[minor]** `Packages/FoundryKit/Sources/FoundryFeatures/RunConsoleView.swift:178-181 (canStart) vs RunStore.swift:86-87 (start)` — *7.5-7 Shotgun Surgery: the start-eligibility rule (trimmed prompt non-empty AND projectDirectory non-empty) duplicated across view and store*: Identical predicate lives in RunConsoleView.canStart and RunStore.start's guard; a change to eligibility (e.g. min prompt length) forces synchronized edits in two modules, and a forgotten copy drifts silently. → **Expose the predicate once on RunStore (e.g. `func canStart(projectDirectory:) -> Bool`) and have the view read it; the store's guard reuses the same predicate. No visual change (button-enable logic unchanged). Note: the store's guard is legitimate defense-in-depth, so keep it delegating to the shared predicate rather than deleting it.**

#### 08-open-closed-principle — Codebase substantially honors OCP: DIP ports invert policy→infra deps, dispatch is centralized in humble objects over closed enums (never re-dispatched), catalogs are data-driven. Only two minor leaf smells where a data-extension is broken by a code edit.

- **[minor]** `Packages/FoundryKit/Sources/FoundryFeatures/Onboarding/OnboardingContainer.swift:147 (screen switch) with OnboardingModel.swift:71 (stepCount=6) and scattered go(to: literal) at OnboardingModel.swift:167,176,182,191,205 and OnboardingContainer.swift:148` — *Form 2 (adjacent) — один дискриминатор шага разобран/зашит в нескольких местах; расширение потока правит существующий код в N точках*: The wizard's screen identity is a raw Int discriminator: a switch by step index picks each screen, stepCount is a separate literal, and next-step targets are hardcoded literals (go(to:1/2/3/4/5)) across model and container.
